# ТЗ для программиста — Nocturne (top-down slasher)

Источник: `Docs/Concept.md` — источник правды по дизайну. При противоречии ТЗ и концепта приоритет у концепта.
Стек и правила работы: `AGENTS.md`.

## 1. Общее описание

Жанр: top-down slasher, 2D, URP.
Сеттинг: сон-кошмар без фиксированной визуальной логики.
Структура: **две сцены**:
1. `MainMenu` (`Assets/Scenes/MainMenu.unity`) — главное меню с титрами;
2. `GameLevel` (`Assets/Scenes/SampleScene.unity` — текущий файл, при необходимости переименовать в `GameLevel.unity` через Editor) — основной игровой уровень.

Игровой мир внутри `GameLevel` — одно большое непрерывное пространство без загрузочных экранов и жёстких границ. Зоны различаются визуально, но соединены бесшовно. Делить игровой мир на несколько сцен запрещено — только связка `Меню → Уровень`.

Игровой цикл (по концепту):

```text
Старт → исследование → бой → очки → выбор маршрута → открытие прохода →
повышение сложности → дальнейшее исследование → Финиш
Смерть → Старт → проход по уже открытой части → фарм → следующий проход
```

Ключевое решение игрока: `накопить на дорогой проход или открыть дешёвый и пойти другим маршрутом?` Каждое открытие навсегда упрощает маршрут, но навсегда повышает сложность.

## 2. Технологические ограничения (обязательно)

- **Целевая платформа — браузер (WebGL).** См. §2.1.
- Unity `6000.3.23f1`, URP `17.3.0`, **2D Renderer** (`Assets/Settings/Renderer2D.asset`). Не использовать 3D-лайты/3D-шейдеры. Освещение только 2D (если нужно).
- New Input System `1.20.0`. Использовать существующий ассет `Assets/Settings/InputSystem_Actions.inputactions`. Не добавлять legacy `Input.GetAxis` и второй actions-ассет без причины.
- Используемые экшены (карта `Player`):
  - `Move` (Vector2): WASD/стрелки/левый стик — движение персонажа.
  - `Attack` (Button): LMB / `Enter` / Gamepad West — удар.
  - `Interact` (Button, Hold `0.6с` из `BalanceConfig`): `E` / Gamepad North — открыть проход (только завершённый холд).
  - `Pause` (Button): `Esc` — пауза в `GameLevel`.
  - `Look`, `Jump`, `Sprint`, `Crouch`, `Previous`, `Next` — **не использовать в MVP**, не маппить на логику без отдельного решения.
- Код: маленькие `MonoBehaviour` в `Assets/Scripts/`. `.asmdef` создавать только при реальной нужде в разделении компиляции.
- Сцены (ровно 2 в билде): `MainMenu` (index 0, старт приложения) и `GameLevel`/`SampleScene` (index 1). Переход только `Меню → Уровень` и обратно (`Победа → Меню`) через `SceneManager.LoadScene`. Внутри `GameLevel` никаких `LoadScene` между зонами. Список билда — `EditorBuildSettings.asset` (`m_Scenes`).
- Тесты: пакет Test Framework `1.6.0`. Проверки через Editor Test Runner (EditMode/PlayMode). PlayMode-сцены эфемерны (`.gitignore` режет `InitTestScene*`).
- Нельзя коммитить: `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `*.sln`, `*.csproj`. Каждый новый ассет коммитить вместе с `.meta` (переименование только через Editor, чтобы сохранить GUID).

### 2.1 Целевая платформа — браузер (WebGL)

1. Build Target: `WebGL`. Проверочные браузеры: свежие десктопные Chrome / Edge / Firefox (Safari — по возможности). Разрешение-референс: `1280×720`, канвас масштабируется под окно (UGUI Canvas Scaler — `Scale With Screen Size`).
2. Ввод: приоритет клавиатура + мышь (`Move` — WASD/стрелки, `Attack` — LMB, `Interact` — E, `Pause` — Esc). Геймпад/тач — как есть из текущего actions-ассета, специально не допиливать. Pointer Lock не использовать.
3. Ограничения WebGL:
    - Автоплей аудио заблокирован до первого жеста пользователя — первый звук только после клика (`Новая игра` считается жестом).
    - Запрещены нативные плагины/DLL, `System.IO` вне `Application.persistentDataPath`, тяжёлые потоки (`System.Threading`) — рассчитывать на один поток.
4. Перформанс-бюджет (джем): цель 60 FPS на среднем ноутбуке; минимум 2D-лайтов, сжатые текстуры/аудио (Sprite — Compressed, аудио — Vorbis), без тяжёлых пост-эффектов URP. Размер билда держать минимальным (Brotli/Gzip компрессия в Build Settings).
5. Приёмка платформы: `Build → WebGL → Run` локально + прогон в чистом браузере (Chrome): меню открывается, уровень грузится без ошибок консоли, звук появляется после клика, просадок управления/ввода нет.

## 3. Термины и сущности

- **Попытка (attempt)** — жизнь от Старта до смерти/финиша.
- **Ран (run)** — последовательность попыток от запуска игры до достижения Финиша. Прогресс рана переживает смерть.
- **Unspent (баланс)** — непотраченные очки текущей попытки. Валюта.
- **Spent (потрачено)** — суммарно потраченные за ран очки на проходы. Метрика прогресса и сложности. Только растёт.
- **Gate (проход)** — дверь/портал/барьер/органика. Имеет `cost`, блокирует путь, открывается навсегда.
- **Start** — единственная точка спавна (старт игры + респаун).
- **Finish** — одна из N альтернативных точек победы. Достаточно достичь любой.

## 4. Сцены: меню и игровой мир

### 4.0 Главное меню (`MainMenu.unity`)

Отдельная лёгкая сцена, стартует первой (index 0). Игрового мира, врагов и `RunState` в ней нет.

Обязательные элементы:
1. Заголовок игры, кнопки: `Новая игра` (→ загрузка `GameLevel`, полный сброс `RunState`), `Титры`.
2. `Титры`: состав команды, использованные ассеты/музыка, версия джема. Отдельная панель в той же сцене, кнопка `Назад`.
3. Реализация: `MainMenuController.cs` + `CreditsPanel.cs`. Дизайн — UGUI + существующий Input action `UI/*`. Никакой игровой логики в меню.

### 4.1 Игровой уровень (`GameLevel`)

Требования к уровню:

1. В сцене ровно один `StartPoint` (пустой GameObject + маркер/тег `Start`).
2. Минимум 2 `FinishPoint` в разных частях карты, с разными маршрутами и разной суммарной стоимостью пути (дешёвый/длинный vs дорогой/короткий — по концепту §2–3).
3. Карта — Tilemap / SpriteShape / спрайты 2D-стека (пакеты уже есть). Коллизии — `Collider2D` + `Rigidbody2D`.
4. Внутри `GameLevel` никаких `LoadScene` между зонами. Переходы только бесшовные (визуальная смена тайлов/декораций/лайтов).
5. Камера: top-down, следует за игроком (`Cinemachine` или простой `FollowCam` — на выбор программиста, без новых зависимостей вне уже установленных пакетов).
6. `GameLevel` не зависит от `MainMenu`: запуск уровня напрямую из редактора должен работать (создать дефолтный `RunState`, если его нет).

### 4.2 Зоны (минимум для MVP)

- Зона A (стартовая): слабые враги, 1–2 гейта наружу.
- Зона B/C: средняя сложность, развилка к финишам.
- Тупиковые карманы для фарма очков.
- Как правило, маршрут дублируется обходом; линейные choke-отрезки без альтернативы допустимы только у финишей.

## 5. Игрок

### 5.1 Компоненты (предложение)

- `PlayerController` (движение top-down, `Rigidbody2D.MovePosition` или velocity, скорость — конфиг).
- `PlayerCombat` (удар по `Attack`: хитбокс-арка перед игроком, кулдаун, урон).
- `PlayerHealth` (`HP`, `Die()` → событие `OnPlayerDied`).
- `PlayerInteractor` (холд `Interact` в радиусе гейта → запрос на открытие, см. §7.1).
- Баланс очков (`Unspent`/`Spent`) хранится только в `RunState` (см. §8–9); отдельного кошелька нет.

### 5.2 Параметры (стартовый баланс, настраивается через ScriptableObject)

- `moveSpeed = 5.0` ед/с.
- `maxHP = 100`.
- `attackDamage = 25`, `attackCooldown = 0.35 с`, `attackArc = 90°`, `attackRange = 1.2`.
- `holdTime = 0.6с` (холд `Interact`), радиус интеракта `1.5`, дебаунс гейта `0.5с`, задержка смерти `1.0с`.
- Направление удара — по движению или по курсору/Look — выбрать одно и зафиксировать (рекомендуется: по последнему направлению `Move`, чтобы не зависеть от мыши на геймпаде).

### 5.3 Управление

- Только через Input System экшены из §2. `PlayerInput` в режиме `SendMessages`/`UnityEvents` или сгенерированный C# класс — на выбор, но один подход на весь проект.
- Мапы: меню `MainMenu` — только карта `UI`, уровень `GameLevel` — только карта `Player` (переключение через `PlayerInput.SwitchCurrentActionMap`). `Pause` — из карты `Player`, `UI/Cancel` — только для меню.

## 6. Противники

### 6.1 Требования

- Префабы врагов: минимум 2 типа для MVP (например, `Chaser` — идёт в контакт, `Dasher/Shooter` — рывок или дальний плевок; визуал любой по концепту §7).
- Общий базовый класс/компоненты: `Enemy` (`HP`, `damage`, `scoreValue`, ссылка на `DifficultyScaler`), `EnemyMover` (простой chase top-down), `EnemyAttack` (контактный урон с кулдауном).
- ИИ MVP: `Idle → Chase (агро-радиус) → Attack (радиус удара)`. Без pathfinding-сетки — обход коллизий через физику; если застревают — агро + slide.
- Спавн: ручная расстановка на сцене + опциональные `SpawnerZone` с лимитом живых. При смерти игрока все враги пересоздаются на исходных точках с полным HP (живые тоже сбрасываются) — нужно для фарма по концепту §6–8.
- Стартовые характеристики (всё в `BalanceConfig`): слабый `HP 50 / урон 10 / очки 10`, средний `HP 100 / урон 20 / очки 25`, сильный `HP 200 / урон 35 / очки 50`; агро-радиус `6`, радиус удара `1.0`, скорость `2.5–3.5`. Сходится с `attackDamage = 25` (§5.2): слабый — 2 удара, средний — 4.

### 6.2 Награда

- Убийство → `Unspent += enemy.scoreValue`. Значения: слабый `10`, средний `25`, сильный `50` (старт, тюнить).
- Начисление только через `RunState.AddKill(points)` (см. §9), напрямую из врага в поля состояния не писать.

## 7. Проходы (Gates)

### 7.1 Логика (строго по концепту §3, §6)

1. У каждого гейта: `string id` (уникальный, стабильный, не завязан на имя объекта), `int cost > 0`, `bool isOpen`.
2. Открытие — только холдом `Player/Interact` (`E` / Gamepad North, `holdTime = 0.6с` из `BalanceConfig`): игрок в радиусе `1.5` + холд завершён (`performed`) + `Unspent >= cost` → атомарный `RunState.TrySpend(cost)` (`Unspent -= cost; Spent += cost; isOpen = true`). Дебаунс `0.5с` от повторного старта, двойное списание исключено.
3. Открытый гейт **никогда не закрывается**, в т.ч. после смерти.
4. Физика: закрытый — блокирует проход (`Collider2D enabled`), открытый — отключает коллизию + меняет визуал/анимацию.
5. Отмена холда (без траты, прогресс в 0): отпустил кнопку (`canceled`), вышел из радиуса, получил урон/умер. Холд не стартует при нехватке очков.
6. UI подсказка рядом: `«держи E — открыть (30)» / «держи E — открыть (30), не хватает 10»` + кольцо/бар прогресса холда (см. §10).

### 7.2 Реализация (предложение)

- `Gate : MonoBehaviour` с полями `id`, `cost`, `isOpen`, событиями `OnOpened`, методами `CanOpen(balance)`, `TryOpen(RunState)`. Логика холда — в `PlayerInteractor` + `Gate` (колбэки `Interact.performed/canceled`).
- Регистрация всех гейтов в `GameManager` (`RegisterGate()`, `List<Gate>`) при старте сцены.
- Вид (дверь/портал/барьер) — только визуал/аниматор поверх общей логики. Не плодить классы под каждый вид.

## 8. Очки и сложность

### 8.1 Очки (концепт §4)

- `Unspent` — сбрасывается в 0 при смерти.
- `Spent` — не уменьшается никогда, не возвращается при смерти.
- Трата возможна только на гейты, частичной оплаты/возврата нет.

### 8.2 Сложность = Spent (концепт §5)

- Единственный источник сложности: `RunState.SpentTotal`.
- Формула MVP (линейно-ступенчатая, тюнится одним SO; стартовые дефолты): `N = 100, K = 0.25, M = 0.15, maxLevel = 5`:
  - `level = min(1 + SpentTotal / N, maxLevel)` (каждые N потраченных — новый тир).
  - множитель HP врагов: `1.0 + K * (level - 1)`.
  - множитель урона: `1.0 + M * (level - 1)`.
  - Можно указать префабы спавнящихся противников в соответствии с каждым тиром.
- `DifficultyScaler` — один класс, читает `SpentTotal`, отдаёт множители. Запрещено размазывать формулы по врагам.
- Сложность применяется к **вновь заспавненным / респауненным** врагам.

## 9. Смерть, респаун, состояние рана

Таблица (строго по концепту §6):

| Состояние | После смерти |
|---|---|
| Позиция | `StartPoint` |
| `Unspent` | `0` |
| `Spent` / сложность | сохраняется, не уменьшается |
| `isOpen` всех гейтов | сохраняется |

Реализация:

- `RunState` (или `GameManager` + `RunState`): единственный владелец `Unspent`, `SpentTotal`, `OpenedGateIds: HashSet<string>`. API: `AddKill(points)`, `TrySpend(cost)`, `ResetAttempt()` (обнуляет только `Unspent`). Создаётся при входе в `GameLevel` (`Новая игра` из меню — всегда сброс; прямой запуск сцены в редакторе — автосоздание). Внутри `GameLevel` живёт весь ран и не уничтожается при респауне (синглтон на сцене). При возврате в меню (кнопка `В меню`/победа) — уничтожается/сбрасывается; `DontDestroyOnLoad` между `MainMenu ↔ GameLevel` не использовать в MVP (состояние рана не переносить в меню).
- `AttemptState` — не отдельный класс, а данные попытки внутри `AttemptResetter` (позиция спавна, HP, точки спавна врагов).
- `DeathFlow`: `PlayerHealth.Die()` → задержка `1.0с` / экран смерти → `Unspent = 0` → игрок на `StartPoint` с полным HP → враги пересозданы на исходных точках → гейты не трогать.
- Разделить код: `RunState` (персистент рана) vs `AttemptResetter` (сброс попытки). Смешивать в одном классе запрещено.

## 10. Победа, поражение, UI

- Победа: триггер `FinishPoint` (любой) → экран победы в `GameLevel` (какой финиш, `Spent`, смерти, время) + кнопки `В меню` / `Новая игра`. Ран завершается, `Новая игра` и возврат в меню сбрасывают `RunState` полностью.
- Поражение попытки: только смерть (экрана game over всего рана нет — сразу респаун по циклу). Кнопка `В меню` на экране смерти — опционально.
- HUD уровня (`GameLevel`):
  - HP, `Unspent` (текущие очки), `Spent` (сложность/прогресс), счётчик смертей.
  - Контекстная подсказка гейта (`GatePrompt`): `«держи E — открыть (30)» / «держи E — открыть (30), не хватает 10»` + кольцо/бар прогресса холда.
- Экраны уровня: старт рана (короткий брифинг), смерть (короткая), победа. Пауза обязательна: `Player/Pause` (Esc) → `GameManager.TogglePause()` (`Time.timeScale 0/1`), экран паузы (`Продолжить` / `В меню`).
- UI меню — только в `MainMenu` (§4.0), UI рана — только в `GameLevel`. Общие префабы (кнопки/шрифты) — в `Assets/Prefabs/UI/`.

## 12. Тесты и приёмка

### 12.1 Автотесты (Test Runner, минимум)

- EditMode: `RunState.TrySpend` уменьшает `Unspent` и растит `Spent`; нехватка — отказ; `ResetAttempt` обнуляет только `Unspent`; `DifficultyScaler` растёт с `Spent` и не падает; дефолты `BalanceConfig` (`N=100, K=0.25, M=0.15, maxLevel=5, holdTime=0.6`).
- PlayMode: открыть гейт холдом → смерть → гейт открыт, `Spent` сохранён, `Unspent == 0`, игрок на Старте; отмена холда (отпустил/вышел) — траты нет; `Pause` останавливает время и показывает экран паузы.

### 12.2 Ручная приёмка (Definition of Done)

1. В билде ровно 2 сцены: `MainMenu` (index 0, запуск приложения) и `GameLevel`/`SampleScene` (index 1). Запуск идёт в меню, кнопка `Новая игра` грузит уровень.
2. Меню: работают `Новая игра`, `Титры`.
3. От Старта до каждого из ≥2 Финишей можно дойти только через гейты; суммарные стоимости маршрутов различаются. Внутри уровня нет загрузок/дозагрузок сцен.
4. Фарм: убийства дают очки, очки тратятся на гейт только завершённым холдом, гейт открывается навсегда.
5. Смерть: задержка `1.0с`, респаун на Старте, `Unspent=0`, гейты открыты, враги пересозданы с полным HP и стали сильнее или того же уровня (никогда слабее).
6. Достижение любого Финиша завершает ран экраном победы.
7. Управление только `Move/Attack/Interact/Pause` из карты `Player` (приоритет — клавиатура+мышь в браузере).
8. Нет legacy-ввода, нет 3D-света, нет лишних сцен в билде. WebGL-билд по §2.1 собирается и играется в Chrome без ошибок консоли.

## 13. Объём MVP и порядок работ (джем)

1. Каркас: `RunState`, `GameManager`, `SceneLoader`, `Start/Finish`, `Gate` с 2 тестовыми гейтами, HUD-числа.
2. Игрок: движение + удар + HP + смерть/респаун.
3. Враг: 1 тип + очки + респаун при смерти.
4. Гейты (Hold `0.6с`, радиус `1.5`, дебаунс `0.5с`) + трата + персист открытости + промпт с прогрессом.
5. Сложность от `Spent` + 2-й тип врага.
6. Карта: ≥3 зоны, ≥2 финиша с разными ценами маршрутов.
7. `MainMenu`: панели `Новая игра / Титры`.
8. Экраны уровня (старт/смерть/победа/пауза + `В меню`), звук-заглушки, баланс-проход, тесты из §12.

## 14. Запреты (не делать без согласования)

- Не делить игровой мир на сцены: зоны остаются внутри `GameLevel`, загрузочные экраны/границы между зонами запрещены. Разрешена только вторая сцена `MainMenu`.
- Не менять смысл очков: убийство → `Unspent`, гейт → `Unspent -= cost`, `Spent += cost`, смерть → `Unspent = 0`.
- Не сбрасывать `Spent`/сложность/гейты.
- Не вводить вторую валюту, магазин, прокачку, сохранения между запусками в MVP.
- Не расширять Input (прыжки/спринт/красться) — это сломает баланс top-down слашера и scope джема.
